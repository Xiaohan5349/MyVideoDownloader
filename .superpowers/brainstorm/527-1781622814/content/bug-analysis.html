Bug Root Cause Analysis

What's actually broken and why

🐌 #1 — Slow UI Updates (3 sub-issues)

Initial load delay loadMedia() does a full round-trip: popup → background → chrome.storage → response. Then loadHelperStatus() fires separately via HTTP fetch. Both are sequential, not parallel.
Click-to-job lag After clicking Download, startDownload() waits for background.js to POST to helper and get a response. The helper then fetches the manifest URL and spawns ffmpeg — all before the popup sees any job ID. No optimistic UI.
Progress polling Job poll is 1s interval (fast enough), but helper status poll is 2s. The issue is that the popup re-renders the entire job list on every poll tick via renderHelperJobs(), destroying and recreating all DOM nodes.

🔘 #2 — No Download Feedback

Root cause The download button does not disable on click, show a spinner, or change text. button.disabled is only set based on item.isProtected at render time (popup.js:149). The async startDownload() takes 500ms–2s to return, during which the button looks clickable.
Result Users click multiple times → multiple ffmpeg processes spawn for the same video → duplicate downloads.

📁 #3 — Folder Button Not Working

Root cause isSafeDownloadPath() at server.js:484 has a flawed check. When the helper download dir is on a different drive than the project (e.g. downloads on D:, project on C:), path.relative() can return an empty string or a path starting with .., causing the safety check to reject valid paths and return 403.
