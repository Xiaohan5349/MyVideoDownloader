Implementation Design

Detailed changes organized by file, with no cross-subagent conflicts

Workstream Split (2 subagents, zero conflicts)

Subagent A: Bug Fixes Touches src/popup.js, src/popup.css, helper/server.js (isSafeDownloadPath only)
Subagent B: History Feature Touches helper/server.js (job persistence), src/background.js (chrome.storage cache), src/popup.js (display merged jobs)
Conflict surface Both touch server.js and popup.js. Subagent A runs first, Subagent B builds on top. Or: use separate functions/regions in each file to avoid merge conflicts.

🅰️ Subagent A: Bug Fixes (popup.js + popup.css + server.js)

Fix A1 — Parallelize popup load

Change popup.js init from sequential:

await loadSettings(); await loadMedia(); await loadHelperStatus(); setInterval(loadHelperStatus, 2000);

To parallel:

await Promise.all([loadSettings(), loadMedia(), loadHelperStatus()]); setInterval(loadHelperStatus, 2000);
Fix A2 — Targeted DOM updates in renderHelperJobs

Instead of helperJobs.textContent = "" + full rebuild each tick, use a Map<jobId, DOMElement> to track existing job rows. Update only changed fields (status, progress text) via data attributes. Only create/destroy rows when jobs appear/disappear.

Fix A3 — Optimistic download button

In startDownload():

button.disabled = true; button.textContent = "Starting..."; statusContainer.hidden = false; statusContainer.textContent = "Connecting to helper..."; statusContainer.classList.add("is-pending");
Fix A4 — Double-click guard

Maintain a const pendingDownloads = new Set() in popup.js. Before calling background, check if URL already in set. Add on click, remove on response (success or failure).

Fix A5 — New CSS: .is-pending pulsing state

Add to popup.css:

.job-status.is-pending { color: var(--cyan); animation: pulseRunning 2.4s ease-in-out infinite; }
Fix A6 — Fix isSafeDownloadPath (server.js:484)

Replace broken relative-path logic:

function isSafeDownloadPath(value, baseDir) { if (!value) return false; const resolved = path.resolve(value); const base = path.resolve(baseDir); // On Windows, compare case-insensitive; on all platforms, check prefix return resolved.toLowerCase().startsWith(base.toLowerCase()); }

🅱️ Subagent B: History Feature (server.js + background.js + popup.js)

Feature B1 — helper-jobs.json persistence (server.js)

New constant: JOBS_PATH = path.join(__dirname, "helper-jobs.json"). On startup, load jobs from disk into the Map. After every job state change (queued→running→completed/failed/cancelled), write the full Map to disk atomically (write to temp file, then rename). Only persist completed/failed/cancelled jobs + active jobs. Add to .gitignore.

Feature B2 — chrome.storage cache (background.js)

New message type: DOWNLOADS_JOB_SYNC. After each successful job poll, background caches the last 20 jobs to chrome.storage.local under key "recentJobs". On popup open, load cached jobs immediately before the helper responds.

Feature B3 — Merged job display (popup.js)

loadHelperStatus() now merges chrome.storage cached jobs with live helper jobs, deduplicating by job ID. Active jobs always win over cached. Shows "20 most recent" cap in popup.

Feature B4 — Dashboard already shows full history

No dashboard changes needed — it already renders all jobs from GET /jobs. After persistence, it automatically shows history across restarts.
